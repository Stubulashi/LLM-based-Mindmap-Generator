## 1. Overview

This project has built a comprehensive, multi-dimensional evaluation system for mind maps generated by large language models. The system covers the complete closed-loop pipeline from audio transcription and mind map generation to quality assessment and report output. It supports multiple operating modes to accommodate different usage scenarios, from exploratory single experiments to large-scale regression testing.

## 2. Input Data Preparation

The evaluation pipeline requires four types of input data: gold standard mind maps in JSON format, core concept sets for entity recall assessment, audio files (WAV or MP3) as the starting point of the pipeline, and human rating scores for correlation analysis. Gold standard maps and generated maps share the same data structure definition, ensuring an apples-to-apples comparison throughout the evaluation process.

## 3. Evaluation Method Selection

The evaluation framework offers three operating modes. The interactive CLI mode guides users step by step through method selection, file upload, and parameter configuration for exploratory experiments. The batch mode automatically scans directories for audio-gold pairs and executes the full pipeline on each pair, generating a consolidated summary report. The demo mode loads built-in example data to quickly demonstrate the entire evaluation workflow, making it suitable for training and presentation purposes.

## 4. Evaluation Pipeline

The complete pipeline follows a three-stage workflow: transcription, generation, and evaluation. In the first stage, the Whisper model transcribes the raw audio into text. In the second stage, a large language model generates a structured mind map from the transcript using a specifically crafted prompt. In the third stage, six evaluation dimensions are executed in sequence to assess label quality, hierarchical structure, downstream question answering, efficiency and transcription quality, multilingual capability and robustness, and alignment with human ratings.

## 5. Internal Review Process

To produce high-quality gold standard data for the label and hierarchy evaluation dimensions, we designed and practiced a team-based collaborative workflow. This process ensures that the reference data used for automated evaluation reflects genuine human judgment and follows a consistent format.

### 5.1 Three-Person Independent Mind Map Drawing

Each evaluation cycle begins with three team members receiving the same audio recording of a course lecture. The audio is divided into logical segments if necessary, but each member works on the same content independently. The core rule is strict independence: members must not communicate with each other, share notes, discuss their approach, or reveal their emerging mind maps at any point during this phase. Each member listens to the audio, extracts key concepts, organizes them into a hierarchical structure, and produces a mind map using the same standardized output format. The resulting three maps naturally differ in their depth, coverage, and structural choices, reflecting genuine variation in human cognitive processing.

### 5.2 Group Discussion and Collective Map Selection

Once all three members have completed their independent maps, the team convenes for a structured discussion session. During this session, each member presents their map and explains the rationale behind their choices regarding node labels, parent-child relationships, and overall hierarchy. The team then compares the three maps systematically across several criteria:

- **Completeness**: How many key concepts from the original audio are captured.
- **Accuracy**: Whether the relationships between concepts are factually correct.
- **Structural quality**: Whether the hierarchy is logically organized and appropriately deep.
- **Consistency**: Whether similar concepts are grouped at similar hierarchical levels.

After discussion, the team either selects the single best map that scores highest across these criteria, or combines elements from multiple maps to form a consolidated collective map. The goal is to produce a gold standard that represents the team's best collective understanding, eliminating individual biases while retaining the strongest structural insights.

### 5.3 Generating JSON Files for Label and Hierarchy Evaluation

From the selected collective mind map, the team produces two separate JSON files through either manual or AI-assisted means.

**Manual method**: A designated team member transcribes the final mind map structure into JSON format by hand using a text editor. For the label file, each node is recorded with its text content and unique identifier. For the hierarchy file, parent-child relationships and depth levels are explicitly encoded. The team reviews the JSON output against the visual map to ensure no information is lost or misrepresented during transcription.

**AI-assisted method**: The team takes a screenshot or textual description of the collective mind map and feeds it into a large language model with a prompt asking it to output the map in the required JSON schema. The output is then reviewed and corrected by the team to fix any structural errors or omissions introduced by the model. This approach significantly speeds up the process while maintaining quality through human-in-the-loop verification.

Both methods produce two files from the same map: one dedicated to label evaluation (containing node text and identifiers) and one dedicated to hierarchy evaluation (containing structural relationships and depth information). This separation allows the two evaluation dimensions to operate independently on the same underlying gold standard.

### 5.4 The n+1 Iteration Cycle and Example Embedding

The entire process described above is repeated **n+1** times. The value of **n** is determined by the size of the experimental dataset and the desired statistical reliability; for typical evaluation campaigns, n is set to a number that provides sufficient coverage across different audio sources, speakers, and subject domains.

The additional **+1** iteration serves a distinct purpose. One of the cycles is designated as the "example" cycle. The JSON files produced in this cycle are intentionally set aside rather than being used as evaluation gold standards. Instead, they are embedded directly into the system prompt of the `modify_mind_map` tool as a few-shot example. The embedding works as follows: the prompt contains the raw transcription text alongside the corresponding example gold standard JSON output. The large language model is instructed to follow the same structure, depth, and formatting conventions demonstrated in the example when processing subsequent audio inputs. This few-shot strategy forces the model to produce outputs that conform to the exact format required by the automated evaluation pipeline, eliminating format variability issues that would otherwise break the downstream comparison.

### 5.5 Impact on the Automated Evaluation Pipeline

The internal review workflow has a profound impact on the downstream automated evaluation. First, it ensures that the gold standard data is of high quality and reflects genuine human consensus, providing a reliable reference for all automated metrics. Second, the example embedding technique standardizes the LLM output format, making the subsequent Hungarian alignment, edge matching, and entity recall calculations possible without manual intervention. Third, by separating label and hierarchy concerns into distinct files, the workflow enables independent diagnosis of which aspect of mind map generation needs improvement. Overall, this process bridges the gap between human judgment and automated evaluation, creating a robust foundation for iterative system improvement.

## 6. Composite Score and Report Generation

After all six dimensions are evaluated, the system computes a composite score by aggregating core indicators from each dimension with predefined weights. Each indicator is compared against a threshold band to determine its performance grade. The system then renders a complete Markdown report containing a summary table, detailed per-dimension results, composite score breakdown, and diagnostic suggestions for optimization. Missing dimensions are handled through automatic weight normalization.

## 7. Operating Mode Comparison

The three operating modes serve different needs. Interactive CLI mode is ideal for single experiments where the user wants fine-grained control over each step. Batch mode automates large-scale evaluation runs by pairing audio files with gold standards through filename matching, generating a comprehensive summary report with statistics. Demo mode provides a zero-interaction walkthrough using built-in sample data, suitable for framework validation and team onboarding. Each mode shares the same underlying evaluation engine, ensuring consistent metrics across all usage scenarios.

## 8. Dual-Track Archiving and Observability

Each evaluation run produces two types of output. Debug output is saved to a timestamped directory containing intermediate artifacts from every pipeline stage, enabling detailed troubleshooting. Persistent evaluation session data is archived to a dedicated sessions directory for future query and historical comparison. Timing instrumentation is embedded at key pipeline nodes to record stage-level latency, providing direct data for the efficiency evaluation dimension.

## 9. Key Technology Bridge

A semantic aligner sits at the core of the evaluation system, serving as the bridge between multiple evaluation dimensions. It encodes node labels from both the gold standard and the generated map into high-dimensional vectors using a multilingual embedding model, computes a cosine similarity matrix, solves the optimal one-to-one assignment using the Hungarian algorithm, and filters matches by a threshold. The resulting alignment simultaneously feeds into both label quality assessment and hierarchy structure evaluation, ensuring metric consistency and traceability across dimensions.

## 1. 概述

本项目构建了一套完整的、多维度的思维导图质量评估体系，覆盖从音频转录、导图生成、质量评测到报告产出的全链路闭环。评估体系支持多种运行模式，可适应从探索性单次实验到大规模回归测试的不同场景需求。

## 2. 输入数据准备

评估管线需要四类输入数据：JSON 格式的金标准导图、用于实体召回率评估的核心概念集合、作为管线起点的音频文件（WAV 或 MP3），以及用于相关性分析的人工评分数据。金标准导图与生成导图共享同一数据结构定义，确保评估过程中的可比性。

## 3. 评估方法选择

评估框架提供三种运行模式。交互式 CLI 模式引导用户逐步完成方法选择、文件上传和参数配置，适合探索性实验。批量模式自动扫描目录进行音频与金标准的配对，对每对数据执行完整管线并生成汇总报告。示例演示模式加载内置数据快速演示评估流程，适合培训和展示场景。

## 4. 评估执行管线

完整管线遵循转录、生成、评测三阶段流程。第一阶段通过 Whisper 模型将音频转录为文本。第二阶段利用大语言模型结合转录文本与特定提示词生成结构化思维导图。第三阶段执行六大维度的评估，分别考察节点标签质量、层级结构正确率、下游问答效果、效率与转录质量、多语言能力与鲁棒性，以及与人评的一致性。

## 5. 组内评审环节

为生产高质量的 label（节点标签）和 hierarchy（层级结构）评估所需的金标准数据，我们设计并实践了一套基于团队协作的工作流。该流程确保用于自动化评估的参考数据反映真实的人类判断，并遵循一致的格式规范。

### 5.1 三人独立绘制思维导图

每个评估周期开始时，三名团队成员领取同一段课程录音。音频可按需划分逻辑段落，但所有成员均独立处理相同内容。核心规则是严格独立：成员之间不得交流、共享笔记、讨论方法或在绘制阶段透露任何进展。每位成员独立聆听音频、提取关键概念、将其组织为层级结构，并使用相同的标准化输出格式绘制导图。最终产出的三份导图在深度、覆盖面及结构取舍上自然存在差异，反映了人类认知加工过程中的真实变异。

### 5.2 组内讨论与集体导图选取

三名成员完成独立绘制后，团队召开结构化讨论会议。每位成员展示自己的导图，解释节点标签、父子关系以及整体层级的选择依据。团队按照以下标准系统性地比较三份导图：

- **完整性**：导图捕捉到了原始音频中的多少关键概念。
- **准确性**：概念之间的关系是否符合事实。
- **结构质量**：层级组织是否逻辑清晰且深度适当。
- **一致性**：相似的概念是否被归入相近的层级位置。

讨论之后，团队要么选出在上述标准上综合评分最高的单份导图，要么从多份导图中选取最优元素融合为一份集体导图。目标是产出一份代表团队最佳集体理解的金标准，消除个体偏差的同时保留最强的结构洞见。

### 5.3 制作 Label 和 Hierarchy 两份 JSON 文件

从选定的集体导图出发，团队通过手动方式或 AI 辅助方式制作两份独立的 JSON 文件。

**手动方式**：一名指定成员使用文本编辑器将最终导图结构逐项转录为 JSON 格式。对于 label 文件，每个节点记录其文本内容和唯一标识符。对于 hierarchy 文件，父子关系和层级深度被显式编码。团队对照可视化导图审阅 JSON 输出，确保转录过程中不丢失或误表达任何信息。

**AI 辅助方式**：团队对集体导图进行截图或提供文字描述，将其输入大语言模型，并要求按所需的 JSON 模式输出导图结构。模型输出的结果由团队检查并纠正任何结构错误或遗漏。该方法通过人在回路中的校验机制大幅提升效率，同时保证质量。

两种方式从同一导图产出两份文件：一份专用于 label 评估（包含节点文本与标识符），一份专用于 hierarchy 评估（包含结构关系与深度信息）。这种分离使得两个评估维度可以在同一金标准基础上独立运作。

### 5.4 n+1 次循环与示例嵌入

上述完整流程重复执行 **n+1** 次。**n** 的大小由实验数据集规模和所需的统计可靠性决定；在典型的评估方案中，n 被设定为足以覆盖不同音频来源、说话人和学科领域。

额外的 **+1** 次循环有独特用途。其中一次循环被指定为"示例"循环。该循环产出的 JSON 文件不会被当作金标准用于评估，而是被直接嵌入到 `modify_mind_map` 工具的系统提示词中作为少样本示例。嵌入方式如下：提示词中同时包含原始转录文本和对应的金标准 JSON 输出，大语言模型被要求在处理后续音频时遵循示例中展示的结构、深度和格式惯例。这种少样本策略强制模型产出符合自动化评估管线所需格式的输出，消除了可能导致下游对比失败的格式变异问题。

### 5.5 对自动化评估管线的实际影响

组内评审工作流对下游自动化评估产生了深远影响。首先，它确保金标准数据具有高质量且反映真实的人类共识，为所有自动化指标提供了可靠的参考基准。其次，示例嵌入技术标准化了 LLM 的输出格式，使得后续的匈牙利对齐、边匹配和实体召回率计算无需人工干预即可顺利进行。第三，通过将 label 和 hierarchy 拆分为独立文件，该工作流支持独立诊断导图生成中具体哪个方面需要改进。总体而言，该流程弥合了人类判断与自动评估之间的差距，为系统的迭代优化奠定了坚实基础。

## 6. 综合评分与报告生成

六大维度评估完成后，系统从每个维度选取核心指标，按预设权重聚合为综合评分。每个指标与阈值带区对比以判定其表现等级，最终渲染为包含摘要表、逐维度结果、综合评分分解和诊断建议的完整 Markdown 报告。缺失维度通过权重自动归一化处理。

## 7. 运行模式对比

三种运行模式服务于不同需求。交互式 CLI 模式适合单次实验，用户可以对每个步骤进行精细控制。批量模式通过文件名匹配自动配对音频与金标准，大规模运行评估并生成含统计数据的汇总报告。示例演示模式使用内置示例数据提供无需交互的快速演示，适合框架验证和新人培训。各模式共享同一底层评估引擎，确保所有使用场景下的指标一致性。

## 8. 双轨存档与可观测性

每次评估运行产生两类输出。调试输出保存至带时间戳的目录，包含各管线阶段的中间产物，便于详细的问题排查。评估会话数据持久化归档至专用会话目录，支持后续查询和历史对比。计时仪表化逻辑嵌入管线关键节点以记录阶段级延迟，为效率评估维度提供直接数据来源。

## 9. 关键技术桥梁

语义对齐器是评估体系的核心组件，也是连接多个评估维度的桥梁。它使用多语言嵌入模型将金标准与生成导图的节点标签编码为高维向量，计算余弦相似度矩阵，通过匈牙利算法求解全局最优一对一匹配，并按阈值过滤匹配结果。该对齐结果同时服务于节点标签评估和层级结构评估，确保跨维度的指标一致性与可追溯性。
